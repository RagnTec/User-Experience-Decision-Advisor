# 动态续谈与自由分支协议 v0.3.3

## 目的与适用边界

本协议管理**分析完成之后**的下一步推荐，不改变专业评审与场景发现的分析方法。目标是帮助使用者更快推进当前产品/业务决策，而不是强迫用户从预置菜单中选一项。对话继续完全可由用户自行发起，**始终接受自由文字输入**；任何推荐都不是必选步骤。

## 内部决策顺序（不必向用户展示）

1. **先完成当前结果**：输出本次已足以支持的结论与依据；没有用户数据不构成阻断。不要用“请选择下一步”替代本轮专业产出。
2. **寻找真正的下一步瓶颈**：只基于当前输入、分析发现和明确未知，选出当前最可能改变决定的事项：例如技术基线待核、备选方案差异未明、重要任务场景遗漏、公开法规/市场陈述待核、需要形成跨团队可沟通的交付物、无需额外动作。
3. **判断推荐是否有增量价值**：每个候选需能说清 **它回答什么当前未解决的问题、预计支持什么行动、缺少什么输入（如有）**。内容必须与本案例绑定，不机械列出 O/D/E/H5；不得依据未经确认的市场判断、技术能力或编造的统计结果推荐方向。若无高价值续谈建议，就自然结束，不显示选项。
4. **少量、差异化推荐**：通常 1–2 个，复杂案例最多 3 个；按对当前业务决策的关联性排序。可以是问题澄清、某一条件分支、对具体候选路径深化、核对关键证据或生成 H5 等。只有可视化能实质降低理解成本且宿主可创建文件时才推荐 H5，且用户未要求或接受前不能自动生成。
5. **自定义与自然语言同权**：只要列出候选分支，就并列提供 `自定义下一步：直接输入你想继续讨论的问题、约束或交付物`。宿主若有原生选项/自由文本工具，使用其实际支持的功能；如原生选项不支持自由输入，仍须明确提示可直接在对话框手动输入，不得伪称存在自由输入控件。用户选择“自定义”却未写内容时，只问一句具体要继续解决什么；用户已输入内容则直接理解并执行，不逼迫回到编号列表。
6. **记忆边界与停止**：对同一任务继承已经核实的内容、材料、拒绝过的选项和呈现偏好；自由输入如改变目标，按最新意图决定局部更新还是切换任务。用户拒绝/跳过或已明确结束时不再推荐；用户后续主动提出新需求则可重新判断。不要保存到 Skill 文件或跨项目挪用任何专有资料。

## 输出样式：只是原则，不是固定菜单

先给结果，再视必要追加**一段**简洁续谈建议，例如：

`如果要推动当前方案评审，下一步更值得处理的是：①核对 A/B 在关键任务状态下的差异（影响是否可以直接选型）；②补充一个错误恢复流程的对照草案（影响实施范围）。另外可直接输入自己希望讨论的问题或交付形式。`

- 不要所有案例都给 ①/②/③；不应固定放置 `生成 H5`、`继续细化`、`保持文字`。
- 显示选项是**快捷方式**，不是封闭式表单。`自定义` 不算在 1–3 个专业推荐候选名额中。
- 媒介建议属于一个可能的动态分支，不比用户新的业务问题更优先。用户已拒绝 H5 时不再次推荐。
- 只有在本轮确实需要用户作决定才能继续分析时，才把选项放在分析之前。否则应先输出可用结论。

## 跨领域案例（全部为独立虚构任务，非市场事实）

**公共自助终端，已有两个流程方案**：若关键差异是“会话结束是否清除敏感信息”，下一步优先推荐核实会话终止规则或比较退出恢复路径；不因为流程有多页就默认推 H5。

**家用小电器的海外产品方向探索**：若尚未确定具体市场/产品类别，推荐可以聚焦 `选择一个明确国家和品类，检查实际使用情境`，或者 `核对已提出的海外生活习惯、差评与合规主张`；未经检索不得将“某地区一定更偏爱旋钮或可洗碗机”作为既定事实。用户也可自定义切换成品牌、成本、渠道或独立设计议题。

**空间装置的几何取舍**：如果已形成有条件的几何建议、但相关坐标未知，可推荐索取最少的安装位置/视点来量化；在数据充分时也可推荐几何图解或离线 H5，但只能在用户接受时创建文件。

## 行为验收关键点

- A：不同项目出现**不同**的下一步建议；无高价值建议可不出现菜单。
- B：出现推荐时，总有可见的手动自由输入路径；原生控件不可用时以对话框说明兜底。
- C：用户自由输入新的任务目标时不要求先选编号，并正确沿用/切换已有上下文。
- D：用户拒绝建议后不追问、不降级当前分析；无明确 H5 授权不创建 HTML。
- E：推荐所依据的市场、法规或工程前提如未经核实，必须标记为待核而非当作事实。
