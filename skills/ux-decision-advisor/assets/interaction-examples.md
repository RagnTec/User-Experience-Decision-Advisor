# 使用示例（全部为独立合成任务）

**1. 泛化请求 → 选择**

用户：`我上传了学习类 App 的退出流程，帮我评估下。`

助手：`这次更想要 D 方案取舍、E 用户体验评价，还是 D+E 综合评审？`

用户：`E。`

助手：如果当前附件可读、任务清晰，直接给「基于设计材料的体验预评估」，无需再要求填完整表单。

**2. 已指定 D+E → 直接工作**

用户：`比较两种资料填写流程：A 保留返回前输入、B 清空。目标是减少重复填写且避免下一位用户看见数据，附件包含两种完整步骤。请 D+E。`

助手：不再询问输出类型；若具体任务、流程及关键约束已经足以支持有条件建议，直接给决策简报和体验评价。

**3. 缺关键对照 → 局部结论 + 必要补充**

用户：`想知道 A、B 哪个更好，目前只有 A 的完整截图。我要 D+E。`

助手：不编造 B；如果 A 有明确任务与真实画面，先对 A 做有依据的体验预评估，同时说明需补充 B 的对应关键步骤才能比较优劣。

**4. 复杂案例但用户未指定格式 → 结论先行、推荐可拒绝**

用户：`对比两种公共空间信息屏布局，考虑多人观看、任务连续性、可达性，帮我 D+E。`

助手：先给有依据的初步决策和关键体验依据。若当前瓶颈是跨团队比较布局，且可视化能帮忙核对任务路径，可简短推荐 H5；若当前方案的关键使用条件尚未确认，则应优先推荐澄清相关条件。任何选择中都要有「自定义下一步：直接输入」的入口，用户拒绝或沉默时不生成 HTML。

**5. 用户已经指定 / 拒绝 → 不再劝说**

用户：`只要文字 E，不需要网页。`

助手：直接完成 E 文字版，不重复提示 H5。

**6. 宿主没有文件能力 → 不能推荐不存在的 H5 交付**

用户：`评价复杂的任务流程，没指定格式。`

助手：先完成结构化文字评价；如需要示意仅使用宿主支持的可视化原语，不诱导用户选择当前无法生成的 HTML。

**7. 针对当前项目生成续谈建议，而非固定 H5 三选一**

用户：`我们在设计小型家电，准备先进入某个海外市场，当前只是初步方向。`

助手：先给目标与当前证据支持范围内的 O/D 分析。若品类和国家仍未明确，可推荐 `①选定一个国家和单一产品类目后再细化使用场景；②优先核对本轮涉及的当地使用习惯/合规主张；自定义：直接输入下一步想讨论的问题、约束或交付物`。不能断言海外市场普遍倾向某个功能。不得固定出现 H5 作为第三项。

**8. 自定义自由输入绕过选项**

用户：`都不选。我更关注维修备件和长期可维护性。`

助手：识别这是同一产品的新的研究视角，直接沿用可用产品事实，转而检查维修任务、零件替换和相关用户体验；不要求用户先选择 O/D/E，也不重复推先前的选项。

**9. 无需继续时不呈现多余菜单**

用户：`只要一句话帮我确认这个按钮文案是否符合前后状态。`

助手：给出直接结论和改法，无需在末尾附上所有 Skill 和 H5 选项。用户依然可以直接输入新的需求。
