# 分支选择与呈现载体协议 v0.3.3

## 两类决定相互独立

**任务内容**：O（场景/机会）、D（方案决策）、E（体验预评估）及其必要组合。**呈现载体**：①文字 ②离线 H5 ③文字+H5。用户本轮明确选择 > 当前同一任务的已确认载体选择 > 合理推荐；不让内容选择暗中决定媒介。

### 内容模式

- 方案比较、资源投入、选择优先级 → D；体验价值、摩擦、体验机制 → E；重要两者兼有 → D+E。
- 遗漏场景/任务/需求错判 → O；明确同时要求寻找问题并评审方案 → O + 必需 D/E，不重复堆砌。
- 已在当前项目确认的内容范围直接执行，不重复询问；首次仅识别出内容意图时先以 O/E/D/V 简洁菜单确认一次。局部事实问答无需进入 Router 项目。

## 媒介模式：推荐不是强制

### 1. 用户已指定媒介

- 已说“纯文字” → 直接文字，不推荐 H5、不生成 HTML。
- 已说“需要 H5/HTML/可视化网页” → 文件工具允许时直接生成离线 HTML，无需额外确认；确实不允许时说明限制并交付可用的文字/原生视图。
- 已说“文字+H5” → 提供文字结论及实际创建的 HTML；失败时只说明未生成，不谎报路径。
- 同一任务中曾说“不要 H5/先别生成/维持文字” → 视为明确拒绝，直到用户主动变更才覆盖，不重复建议。

### 2. 用户未指定媒介：按任务特征提出一次**非强制**推荐

- **简单、聚焦、无需图解**（一两个具体触点、小范围取舍、直接问答）：推荐并直接采用文字。可在末尾一句写 `呈现建议：文字版（已按此提供，后续也可改为 H5）`；不要先问一轮，也不必每回合重复。
- **结构复杂且可视化能降低理解成本**（多备选取舍/多人多情境、用户任务链或状态转换、物理空间关系、O+D/E 综合结果、有来源的多指标对照）：若宿主支持文件写入，推荐 `H5 + 简短结论` 或 `文字+H5`，用一句话解释**为什么图解更适合此案例**；不因为专业词多或篇幅长就机械推荐 H5。
- **复杂但宿主不能创建文件**：只推荐可以交付的层次化文字、任务流程或原生可视化；不提出不可执行的 H5 制作选项。

### 3. 不阻断专业分析；必须让用户拒绝

先输出**可独立使用的文字核心结论**（必要时补 2–3 项关键依据和下一步），再按当前案例需要决定是否提供媒介建议。若只需决定是否增加图解，可以简短推荐 H5；若还存在更有价值的决策或证据分支，不得把末尾固定为 H5 三选一。**凡出现选项，必须并列提供「自定义下一步：直接输入你的方向/问题」**；示例只用于展示如何写选项，不能固化成为每轮模板。具体遵循 [动态续谈协议](dynamic-continuation.md)。 

- **用户未选择/忽略建议**：视作维持已提供的文字输出，不自行开始 H5 制作，也不妨碍下一轮对话。
- **用户回复②/拒绝**：尊重，不对同一任务继续推荐，不减少文字分析质量。
- **用户回复①或③**：继承已分析事实、证据和决策，不重新询问分析模式；仅调用专业 Skill 的报告生成协议；生成文件后验证、交付。
- **用户日后主动切换**：仅改变呈现，不重置当前材料；当内容事实发生变更时，只更新受影响分析。
- 宿主有真实选项控件时可用；**无控件时只展示可回复的编号文字**，不能假装已经出现按钮或选项卡。

## H5 内容与安全

方案矩阵、任务链、场景路径、空间关系、证据分层仅在当前数据足以支撑时展示；缺实测不产生统计图、凭空风险分数和人因阈值。不要让视觉效果掩盖科学不确定性。生成前确定文件工具确实可用；不将私有材料上传第三方或引入远程脚本。离线 HTML 仅负责展示，不具备在线 AI 分析功能。

## 轻量切换（不重复）

分析结束后仅当确有高价值后续路径时提出少量**与案例直接相关**的选项；不用固定的 `O / D / E / D+E；文字 / H5 / 两者` 全量菜单。候选与自定义输入同等可选，用户也可以直接描述下一步而不输入编号。用户拒绝某条建议后不再重复，同一任务保留已确认的载体选择。
