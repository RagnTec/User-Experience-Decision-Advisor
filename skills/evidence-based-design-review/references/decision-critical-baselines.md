# Decision-Critical Baseline Check | 决策关键技术基线检查

## 目的与范围

当设计建议依赖**实际实现能力**（传感器、算法性能、识别安全等级、系统权限、通信时延、可靠性、标准/认证范围等）时，不可把行业常态、成本猜测、外观、产品定位或对标对象的实现代入当前方案。此规则适用于不同产品领域，不内置任何产品或企业方案。

**缺失信息只阻断它真正影响的结论**。没有真实用户调研仍可开展专业预评估；没有决定性技术基线时，则不能宣称最终安全能力、兼容性或方案胜负已经确定。

## 内部四步检查（无需在输出中逐项展示）

1. **来源盘点**：把用户明确陈述、附件可核实、公开资料的通用知识、模型自己的推断分开。尤其不要从“市场常见实现”跳到“当前产品就是如此”。
2. **反事实敏感性**：假定两种合理但不同的实现能力：`若能力 X 成立，选择是否倾向 A？若能力 Y 成立，是否倾向 B 或暂缓？` 若判断不变，缺口不阻断；若可能逆转，标为 Decision-Critical Unknown。分支应同等中立，不预设某项实现“更常见”或“更低端”。
3. **最小化求证**：优先问能影响结论的**能力或约束**，而非整套工程规格：例如“是否达到目标系统所要求的生物识别安全类别和适用功能？”或“在目标光照/姿态条件下有什么可核验的失败边界？” 用户如无法提供专有实现详情，可以提供功能能力、适用等级、是否支持特定任务及其验证状态。**不要自动要求金融支付认证**，除非支付/高安全场景属于决策目标。
4. **分层继续**：可独立评价的任务体验先评价（发现性、可达性、姿态、反馈、恢复、操作负担）。技术依赖的安全/可靠性/兼容性和最终方案取舍保持条件化；若选择确实被阻断，先询问一项最关键事实，而不是输出几百字的批判性假设。

## 示例（全为独立泛化示例）

- **移动设备生物识别**：不能因为使用某种指纹传感器，就推定另一项人脸方案只具备普通二维摄像头能力；不能把“配备红外或深度感知”直接等同于满足指定安全等级。解锁便利性与高安全认证应分别比较；安全等级需按适用平台和验证标准核查。
- **定位服务**：没有定位方案及精度说明时，不可从“支持卫星定位”推定达到厘米级精度；如果任务仅为一般行程提醒，可以继续进行条件性体验分析。
- **本地/云端推理**：没有计算和网络条件时不能认定离线一定可用、时延一定低或隐私处理方式已确定；可先分析任务对即时性、失败恢复和授权的需求。
- **对标案例**：公开产品可提供方法参照，但不能证明当前对象具备同等软硬件、系统权限或工程限制；先识别决定对标可迁移性的前提。

## 精简输出模式

**有可执行局部结论时**：`当前可判断：〔具体的用户体验价值和行动〕。但〔受技术基线影响的关键结论〕尚不能定论。关键输入：〔一个能力/约束问题〕；若为 X 倾向 A，若为 Y 则考虑 B。`

**核心选择被阻断时**：`目前不能可靠判定〔具体选择〕，因为〔一项未知能力会改变结论〕。请确认〔最小信息〕。在此之前，可确定的体验取舍是〔1 条有用判断〕。`

避免自我批评、心理化归因、密集技术清单和重复询问；没有充分证据时不说“严重失误源于某认知偏差”。若先前结论基于错误的隐性前提，主动撤回受影响的**具体结论**并说明影响范围，其余已由事实支撑的部分不随之推翻。
