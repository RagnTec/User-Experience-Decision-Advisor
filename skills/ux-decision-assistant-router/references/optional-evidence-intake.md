# Optional Evidence Intake | v0.3.3

## 原则：相关性优先、补充非强制

每种资料只在有助于判断**当前的决策**时才邀请。不是材料越多越好；真实用户研究不是通用前置条件。资料暂时没有、不适合提供、权限不足或选择不提供时，继续能成立的条件性分析，不重复催促。

### 资料类型与可能用途

| 可选资料 | 可能解决的具体问题 | 限制与注意 |
|---|---|---|
| 产品说明、原型、设计稿、任务流程 | 产品究竟怎样工作，任务在哪里发生 | 已展示≠功能穷尽；不可访问附件不能假装读过 |
| 需求来源、立项依据、业务假设 | 识别真实决策目标、约束及需求是否被过度解释 | 需求方主张不等于用户真实需求 |
| 用户问卷、访谈、研究报告 | 用户态度、理解及解释性线索 | 先审样本、题目、时间与适用范围；没有不阻断预评估 |
| VOC、评论、客服与投诉 | 体验摩擦、异常与具体语境 | 反馈覆盖和选择偏差，不可直接推广比例 |
| 脱敏行为日志、任务数据、实验结果 | 真实路径、失败位置、行为或效果量 | 核对事件定义、样本覆盖、去标识与授权；不捏造指标 |
| 公司/组织规则、品牌要求、业务流程 | 特定的限制、交接条件、当前操作流程 | 只作为当前项目获授权的约束，不当作公开普适标准；与安全法规冲突须标出 |
| 工程参数、接口能力、测试记录 | 决策关键技术前提、可达性或人因计算 | 无证据不可假定实现档次；数值要标单位和测量条件 |
| 公开标准、法规、研究 | 查证外部要求及相关体验机制 | 核对原文、版本、适用产品/地区，不用引用代替本产品事实 |

## 推荐消息模板（按案例改写，不固定照抄）

`目前可以先判断〔已经有依据的方向〕。要回答〔本案的关键决策〕，如果方便，最有价值的补充是〔材料 A，为什么〕和〔材料 B，为什么〕。①上传/粘贴已有材料；②没有或暂时不便提供，按现有材料继续；③自定义补充其他条件或调整分析重点。`

最多主动邀请 1–3 个**本案相关**的资料类型；如一类足够则只问一类。不要将全部类别作为用户必填清单。能从已有资料中获得的信息不重问，当前任务与资料无关时不显示该入口。

## 权限与敏感信息

- 用户提供或明确授权访问的资料只用于当前分析；不默认跨会话保留、建立公共知识库或分享给其他 Agent/外部网站。
- 企业内部规范、商业数据、原始用户研究及任何专有字段/映射不可写入公共 Skill、公开样例、回归题库或源代码。演示用完全独立的合成案例。
- 如涉及个人信息、受试者资料或机密信息，优先提示最小化、去标识与访问授权。即使已脱敏也不自动视为可公开。
- 只有真正可读取且权限允许时才声称使用过材料；不能访问时明确说明，允许用户提供不敏感的摘要。
- 来源冲突时清楚区分：用户提供的产品事实、内部约束、已验证外部要求、行业惯例、模型推断。禁止自动将内部口径提升为普遍结论。
- 外部搜索应使用不包含机密产品/用户数据的通用关键词；未经明确授权不上传私有资料到第三方服务。

## v0.4B.1 VOC opt-in update

If the current decision could benefit from VOC, refer to [VOC Source Routing](voc-source-routing.md). Do not automatically fetch/crawl third-party reviews. A user can supply authorized data, say `not available`, select an outside collection route, or give a different source. A feedback dump without provenance is still useful for generating *hypotheses*, but not for population rates or definitive priority rankings.
